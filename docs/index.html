How everything works.

From installation to encrypted message delivery.

01

Vault Creation

Upon first launch, you set a strong PIN (min 12 chars). LANMess generates a random 32-byte master key and wraps it with Argon2id (time=3, memory=64 MiB, parallelism=4) derived from your PIN.

02

Peer Discovery

The app broadcasts a UDP packet on port 50505 every 2 seconds. Other instances on the LAN hear this and cache your IP, TCP port, and Ed25519 / X25519 public keys automatically. Peers expire after 15 seconds without a broadcast.

03

Secure Adding

To add a peer, you exchange an 8-digit TOTP code that rotates every 60 seconds. The proof is an HMAC-SHA256 over a fresh 32-byte challenge, proving you share the same local network and that you know the peer's current code.

04

Encrypted Chat

A chat request triggers an X25519 ephemeral handshake. HKDF-SHA256 derives independent send and receive ratchets. Each message is padded to 256-byte blocks, encrypted with AES-GCM, and signed with Ed25519.

Cryptographic
Architecture

LANMess does not rely on proprietary security through obscurity. It uses battle-tested, standard cryptographic primitives. Here is how a message is secured:

1

X25519 Handshake

An ephemeral key exchange creates a shared secret that is never sent over the network. The handshake is authenticated by the long-term Ed25519 identity key.

2

HKDF Derivation

The shared secret is expanded into independent send and receive hash chains using HKDF-SHA256 with the sorted ephemeral public keys as salt.

3

AES-GCM & Hash Ratchet

Each message uses a fresh key from the ratchet, pads the payload to a 256-byte block, encrypts with AES-GCM, and immediately advances the chain with HMAC-SHA256.

4

Ed25519 Signatures

Every control frame and message is signed with your long-term identity key to prevent tampering. Signature failures immediately block the contact and are recorded in the audit log.

Engineered for Privacy.

A complete suite of security features designed for hostile network environments.

Terminal Native

Built with Python and Textual. No web views, no Electron. A highly responsive, keyboard-driven interface.

PIN Lockout

Brute-forcing the vault is impractical. 5 failed attempts trigger a 30-second lockout. 10 trigger 5 minutes, 20 trigger 1 hour, and 50 trigger a 24-hour lockout.

Audit Log

Security events are chained with HMAC-SHA256. The database cannot be silently modified without breaking the cryptographic chain.

Auto Discovery

UDP broadcast finds peers every 2 seconds. No need to manually configure IP addresses for peers on the same subnet.

Safety Numbers

Compare a 60-digit fingerprint out-of-band to verify your contact's identity and prevent man-in-the-middle attacks.

Secure Deletion

SQLite PRAGMA secure_delete is enabled and the database runs in WAL mode. Symmetric keys are zeroed out in memory on lock, panic, or shutdown.

Panic PIN

A secondary password hashed with SHA-256. Entering it at the unlock screen instantly wipes the local database and exits the app. Designed for plausible deniability under coercion.

Key Rotation

Generate fresh Ed25519 and X25519 identity keys on demand. Rotation frames are signed with the old key and broadcast to every non-blocked contact, with automatic retry until delivered.

Typing & Presence

Peers see a live typing indicator throttled to once per 1.5 seconds and presence pings every 3 seconds. Online status fades after 15 seconds of silence. Both are signed frames — not encrypted by the ratchet.

Outbox Retry

Messages that fail to deliver are queued in memory and retried every 10 seconds while the session is active. Delivery is acknowledged per frame.

Reply & React

Use /reply <id> <text> and /react <id> <emoji> to embed lightweight references inside the encrypted frame. Recipients see them prefixed in the message view.

Search All

Ctrl+F searches every decrypted message across all conversations (capped at 50 results). No plaintext ever leaves your device — the search runs on the decrypted SQLite view.

What LANMess is not: no file transfer, no images, no group chats, no mobile app, no PIN recovery, no chat history export, no VLAN/subnet support without a VPN, and no plaintext metadata protection for control frames like presence and typing.

Deep Dive FAQ

Everything you need to know about LANMess. Mined directly from the source code.

1. App Setup & The Vault

What is the "Group Code" used for during setup?

The Group Code derives the initial shared network key using PBKDF2-HMAC-SHA256 with 600,000 iterations and the salt "lanmess-group-key-v1". Only users who know the Group Code can generate the same discovery tags and format their packets correctly. It acts as the shared secret for the local network group.

Why must my PIN be at least 12 characters long?

Your PIN unlocks the local vault. The config enforces PIN_MIN_LEN = 12 and requires at least 3 of: lowercase, uppercase, digit, symbol. A weak PIN makes the Argon2id encryption vulnerable to offline brute-forcing if your device is stolen.

What encryption is used for my local database?

Your SQLite database (~/.lanmess/lanmess.db) is encrypted field-by-field. Every data record (identity, contacts, messages, audit entries) is encrypted with AES-GCM under a random 32-byte master key. That master key is wrapped with Argon2id (time=3, memory=64 MiB, parallelism=4) derived from your PIN and stored in the vault table. The DB file is chmod 0o600 and the ~/.lanmess directory is chmod 0o700.

What happens if I fail my PIN multiple times?

LANMess implements escalating lockouts defined in PIN_LOCKOUT_STEPS: 5 failed attempts → 30-second lockout; 10 → 5-minute lockout; 20 → 1-hour lockout; 50 → 24-hour lockout. These are tracked in the database, so restarting the app does not bypass them.

What is the Panic PIN and how does it work?

The Panic PIN is a secondary password you set from the Menu (Menu → Set Panic Password). It is stored as a SHA-256 hash in the security table. When you enter it at the unlock screen, LANMess detects it before attempting any normal unlock, wipes the entire database, deletes the SQLite file and its -wal / -shm / -journal companions, zeroes in-memory keys, and exits. It is designed for plausible deniability under coercion. Note: it does not touch your PIN, only the database.

2. Networking & Discovery

Can I use LANMess over a VPN like Tailscale or ZeroTier?

Yes. LANMess operates on Layer 3 using UDP (port 50505) and TCP (ports 50510–50600). As long as your VPN creates a virtual LAN where broadcast packets or direct IP routing can reach the peers, LANMess will work. You may need to use "Add by IP" if UDP broadcast doesn't traverse the VPN.

What happens if my peer's IP address changes?

The UDP discovery mechanism broadcasts every 2 seconds (DISCOVERY_INTERVAL) and expires peers after 15 seconds (DISCOVERY_TTL). If you added the contact using "Add by IP", it is marked as pinned (pinned=1) and will not auto-update its IP. Unpinned contacts update automatically from discovery and from the source IP of any signed frame they send you.

How does the 8-digit "Add Code" work?

The 8-digit code is a TOTP (RFC 6238-style, HMAC-SHA256) generated every 60 seconds from a random 20-byte secret embedded in your identity record. When peer A wants to add peer B, A reads B's current code from B's "Show add code" screen (Ctrl+Z), enters it, and sends an ADD_REQUEST containing a fresh 32-byte challenge plus an HMAC-SHA256 proof over "REQ" + A's name + challenge using the code as the HMAC key. B verifies against the current and previous 60-second window. This proves shared LAN knowledge without leaking the code itself.

What ports do I need to open in my firewall?

Allow UDP 50505 for discovering peers (DISCOVERY_PORT) and TCP 50510–50600 for sending and receiving actual messages (TCP_PORT_RANGE). Each instance binds exactly one TCP port in that range. If you don't open these, peers will appear offline or messages will fail to deliver.

Does LANMess work across VLANs or subnets?

No, not out of the box. UDP broadcast on port 50505 does not cross VLAN or subnet boundaries. You must either be on the same broadcast domain, use "Add by IP" with a routable address, or tunnel traffic through a VPN that presents a virtual LAN to both peers.

How do presence indicators work, and are they private?

Every active session sends a PRESENCE frame every 3 seconds (PRESENCE_INTERVAL). A peer is shown as online if any signed frame or successful probe has been heard within 15 seconds (ONLINE_WINDOW). Peers are marked offline after two consecutive probe failures. Important: PRESENCE frames are signed with Ed25519 but NOT encrypted by the session ratchet — an observer on the LAN can see that two names are exchanging presence every 3 seconds. Message content is still opaque.

How do typing indicators work, and are they private?

When you start typing in the message input while a session is active, LANMess sends a signed TYPING control frame, throttled to once per 1.5 seconds (TYPING_THROTTLE). Recipients display "(typing)" for 3 seconds (TYPING_DISPLAY_TTL). Like PRESENCE, TYPING frames are Ed25519-signed but not wrapped in the AES-GCM ratchet — so metadata leaks to LAN observers. To hide metadata, use LANMess on a trusted wired network or an encrypted tunnel.

How does the outbox retry queue work?

If a MESSAGE frame times out (MESSAGE_TIMEOUT = 3 s), the text is queued in memory under that contact. A background loop retries every OUTBOX_RETRY_INTERVAL (10 s) while the session remains established. Successful retries remove the entry from the queue. The queue is lost on app restart, session stop, key rotation, lock, panic, or reset — it is a best-effort convenience, not a durable store.

3. Cryptography & Security

What exactly are "Safety Numbers"?

Safety numbers are a 60-digit fingerprint generated by hashing both your Ed25519 public key and your peer's Ed25519 public key. The keys are sorted lexicographically, concatenated as hex, and hashed with SHA-256. The first 60 decimal digits (from f-string 3-digit-per-byte encoding) are displayed. Compare this number with your peer over a secure out-of-band channel (in person, or via a trusted call). If they match, no Man-In-The-Middle can be intercepting your keys.

How does the "Forward Secrecy" hash ratchet work?

For every message sent or received, the symmetric encryption key is destroyed and replaced. The next key is generated by HMAC-SHA256 over the current key with a 1-byte label (CHAIN_NEXT_LABEL = 0x01). The per-message AES key is HMAC-SHA256 with the label CHAIN_MSG_LABEL = 0x02. If an attacker steals your current key, they cannot decrypt past messages, because the old keys were permanently deleted from memory.

What does "Verified-only" mode do?

When enabled in the Menu, LANMess rejects CHAT_START and MESSAGE frames from contacts that are not marked verified (verified=1, where you've compared safety numbers). It enforces a strict zero-trust policy on your contact list.

What happens if a message signature fails to verify?

If an incoming MESSAGE frame fails Ed25519 signature verification, or AES-GCM decryption fails (indicating tampering or wrong key), LANMess immediately sets blocked=1 on the contact, refuses to accept the frame, notifies you, and records the event in the audit log as SIG_FAILURE or DEC_FAILURE. This assumes an active attack.

How does replay protection work?

Every MESSAGE includes a sequential counter. LANMess rejects any message whose counter is less than or equal to the last received counter, and rejects gaps larger than MAX_CHAIN_GAP (1000). Control frames also carry a millisecond timestamp that must be within REPLAY_WINDOW_SECONDS (60) of the local clock.

How does key rotation work?

Menu → Rotate Keys generates a new Ed25519 keypair and a new X25519 keypair on the spot. The old Ed25519 key signs a ROTATE frame containing both new public keys, then LANMess broadcasts the frame to every non-blocked contact over TCP. Peers verify the old signature, update their stored keys, and reply OK. Failed deliveries are queued in _pending_rotates and retried whenever the peer becomes reachable again. Your database is updated with the new private keys before broadcasting.

How does message padding work?

Each plaintext is prefixed with a 4-byte big-endian length, then padded with random bytes to the next multiple of PAD_BLOCK (256). This hides exact message lengths from network observers, though timing and counter progression still reveal message frequency. On decrypt, unpad_message reads the length and slices the plaintext.

What are the per-IP rate limits?

ADD_REQUEST frames are limited to one every ADD_RATE_LIMIT_SECONDS (0.5 s) per peer IP, and MESSAGE frames to one every MSG_RATE_LIMIT_SECONDS (0.05 s, i.e. 20/s) per peer IP. Both limiter dicts cap at ADD_RATE_LIMIT_MAX / MSG_RATE_LIMIT_MAX (4096 entries) and are pruned when exceeded. Excessive traffic returns rate_limited and does not touch the session.

4. TUI Interface & Commands

What is the difference between "/clear" and "/clearall"?

/clear deletes the messages only on your local device. The peer still has their copy. /clearall sends a CLEAR_REQUEST to the peer. If the peer accepts (Y), both sides wipe the conversation from their local databases. It requires mutual agreement to prevent data loss.

How do I completely reset LANMess?

Press Ctrl+R or open the Menu and select "Reset everything". This drops all tables (identity, contacts, messages, vault, audit_log, security, meta), recreates empty tables, resets schema_version to 8, runs a VACUUM, and zeroes out the cryptographic keys in memory. Irreversible.

What do the contact statuses mean?

[active]: session_established=1, the X25519 handshake is complete and the ratchet is set — you can send messages. [waiting]: pending == 1, you sent an add request and are waiting for the peer. [accept?]: pending == 2, the peer sent you a request and you must press Y. [chat req]: incoming_request == 1, the peer wants to start a chat. [legacy]: chat_started=1 but session_established=0 (app restart or network loss); press S to restart the handshake. ● means the peer is online; "(typing)" appears when a TYPING frame was received in the last 3 seconds.

What is the maximum message length I can send?

The maximum message length is 8,192 characters (MAX_MESSAGE_LEN). LANMess refuses longer messages to keep frames within MAX_FRAME_SIZE (64 KiB). Messages containing a NUL byte are also rejected.

How do I reply to or react to a message?

Type /reply <id> <text> to send a new message tagged with the reference id, or /react <id> <emoji> to send a short reaction. IDs are shown as [#id] at the start of each message line. The reference is embedded as extra fields (reply_to, react_to) in the encrypted MESSAGE frame and rendered as "[re #id]" or "[react #id]" on both sides.

How do I search across all conversations?

Press Ctrl+F to open the Search modal. As you type, every decrypted message across all conversations is scanned and up to 50 results are shown, timestamped and labeled with the contact name. Search happens entirely on the local decrypted view; nothing is sent to anyone. For per-contact search inside a chat, use /find <text>.

5. Troubleshooting

Why does it say "Message not delivered: no response"?

This means the MESSAGE frame timed out (MESSAGE_TIMEOUT = 3 s) or the TCP connection was refused. Likely causes: the peer closed the app, their firewall blocks TCP ports 50510–50600, they are on a different subnet/VLAN, or the session was silently dropped. If the session is still active, your text will be retried by the outbox loop every 10 seconds.

Why is my peer showing as offline?

LANMess sends a presence probe every 3 seconds (PRESENCE_INTERVAL). Two consecutive failures mark the peer offline, as does 15 seconds of silence (ONLINE_WINDOW). Check whether UDP port 50505 is open for discovery, whether TCP 50510–50600 is reachable, or whether they disabled presence in their menu. If a chat is active and the peer returns, LANMess auto-reconnects by starting a fresh handshake.

Why did I get blocked by a contact?

If LANMess detects a signature failure, decryption failure, or a counter below the last received counter from your IP, the peer's instance sets blocked=1 on your contact and refuses further traffic. This only happens if the cryptographic integrity of the session is compromised. Blocks are recorded in the audit log.

What does the "Audit Log" warning mean?

The audit log is an HMAC-SHA256 chain: each entry hashes the previous entry's own_hmac together with its own encrypted payload, using a key derived from the master key. The genesis HMAC is 64 zeros. If someone deletes or modifies audit_log rows directly, verify_audit_chain detects the break. That means your database was tampered with outside the app.

What is the session idle timeout?

Every 60 seconds the idle watchdog checks each active chat's last activity timestamp. If 30 minutes pass (SESSION_IDLE_TIMEOUT = 1800), it shows a notification and resets the counter. It does not auto-stop the session — it only warns you. Use /stop or press T to end a session explicitly.

6. Platform & Compatibility

Which CPUs are supported by the pre-built installers?

The one-click installers (Windows .exe and the macOS/Linux shell scripts) are built for Intel and AMD x86_64 processors only. On ARM64 / aarch64 systems — including Apple Silicon Macs, Windows on ARM, and ARM Linux (Raspberry Pi, Asahi, etc.) — do everything manually: install Python 3.9+, then use pip install lanmess, or clone the repository from source. There is no pre-built ARM installer at this time.

What Python version do I need for a manual install?

Python 3.9 or newer is recommended. LANMess depends on the cryptography and textual packages, plus optional Argon2id acceleration via the argon2-cffi package. If argon2-cffi is unavailable, the code falls back to scrypt (n=2^16, r=8, p=1) and then PBKDF2 (2,000,000 iterations). On aarch64, ensure your system packages for libssl and libffi are current before pip install.

Why does my antivirus flag the Windows installer?

The .exe is built with PyInstaller, which is frequently false-positive flagged by antivirus engines because packers are also used by malware. The build is open source and reproducible from the repository. If you prefer, install manually with pip install lanmess to avoid the binary completely.

Is there a mobile app?

No native mobile app exists. LANMess is a terminal UI built with Textual. On Android you can run it inside Termux with pip install lanmess. iOS does not provide a suitable terminal environment, so it is not supported.

7. General

Is LANMess free?

Yes. LANMess is released under the MIT license. There are no accounts, subscriptions, or telemetry. The full source is on GitHub and can be audited or self-built at any time.

What happens if I lose my PIN?

There is no recovery. The PIN wraps a random 32-byte master key with Argon2id, and that master key encrypts every field in your database. Without the PIN, the data is cryptographically inaccessible. Your only options are to restore from a backup of your ~/.lanmess folder, or reset everything and start over.

Can I send files, images, or group chats?

Not yet. LANMess is text-only and one-on-one. There is no file transfer, image embedding, or group chat in the current source. Messages are capped at 8,192 characters. Every message you send is written to the local encrypted database as plaintext inside AES-GCM, so secrets pasted into chat are protected by the session ratchet in transit and by the DB encryption at rest.

How do I update LANMess?

Download the latest release and install over the existing one. Your database at ~/.lanmess/lanmess.db is preserved. Schema migrations run automatically on first launch (current schema_version = 8), so your identity, contacts, and messages survive upgrades from older schema versions.

Can I export my chat history?

There is no built-in export feature. Every message is stored field-encrypted in SQLite using AES-GCM, so a straight SQL dump yields only ciphertext. You can copy the whole ~/.lanmess folder as a backup, but reading it back requires the original PIN and this app.

What happens to an active chat if the network drops?

If either peer restarts the app or loses the network long enough that the process ends, the established session is lost and the contact is marked as [legacy]. Outgoing messages time out and either queue in the in-memory outbox or get returned to the input box. When presence detects the peer online again, LANMess auto-initiates a fresh X25519 handshake (start_chat). The old hash ratchet is never reused.

Does LANMess read my keystrokes or other files?

No. The only files LANMess reads or writes are inside ~/.lanmess: the encrypted SQLite database and its -wal / -shm files. config.py resolves BASE_DIR = Path.home() / ".lanmess" and nothing else. It does not install hooks, background services, or telemetry endpoints.
