How everything works.

From vault initialization to encrypted message ratcheting.

01

Vault Creation

On first launch, you enter your display name, a shared group code (12–256 chars), and a strong PIN (min 12 chars with lower, upper, digit, and symbol). LANMess generates a random 32-byte master key and wraps it with Argon2id (time=3, memory=64 MiB, parallelism=4).

02

Peer Discovery

Instances broadcast UDP beacons on port 50505 every 2 seconds carrying current and previous TOTP-derived code tags and public keys. Peers expire after 15 seconds without a beacon, or you can add directly by IP and TCP port (50510–50600).

03

Secure Adding

To add a peer, you enter their rotating 8-digit TOTP code (60s window). Your request includes a 32-byte challenge and an HMAC-SHA256 proof over the code, verified against the current and previous 60-second window without exposing the code itself.

04

Encrypted Chat

Starting a chat runs an ephemeral X25519 exchange and derives independent send and receive hash chains via HKDF-SHA256. Each message is padded to 256-byte blocks, encrypted with AES-256-GCM, and signed with Ed25519.

Cryptographic
Architecture

LANMess uses standard cryptographic primitives across session setup, message ratcheting, control frames, and local storage:

1

X25519 Ephemeral Exchange

Each chat session generates fresh ephemeral X25519 keys to compute a shared secret while control frames are authenticated by your Ed25519 identity key.

2

HKDF-SHA256 Chain Derivation

The shared secret and sorted ephemeral public keys derive a 64-byte key material split into directional send and receive ratchet chains.

3

AES-256-GCM & Hash Ratchet

Each message derives a per-message key, pads the plaintext to a 256-byte block, encrypts with AES-GCM bound to sender and counter AAD, and advances the chain key via HMAC-SHA256.

4

Ed25519 Signatures & Audit Chain

Messages (including reply and reaction targets) and control frames are Ed25519-signed, while local security events are recorded in an HMAC-SHA256 chained audit log.

    reply_to=0, react_to=0, from_outbox=False

        )

        msg_key = chain_message_key(send_chain)
        padded = pad_message(text.encode("utf-8"))
        nonce = os.urandom(12)
        aad = f"{self.user_name}:{counter}".encode("utf-8")
        ct = aes_gcm_encrypt(msg_key, padded, nonce, aad)

        signed_data = (
            self.user_name.encode("utf-8")
            + counter.to_bytes(8, "big")
            + nonce + ct
            + reply_to.to_bytes(8, "big")
            + react_to.to_bytes(8, "big")
        )
        sig = sign_bytes(self.ed_private, signed_data)
        new_chain = chain_advance(send_chain)
        self.db.set_contact_state(
            contact_name,
            send_chain_key_hex=new_chain.hex(),
            send_counter=counter,
        )

Engineered for Privacy.

A complete suite of security and usability features built into the terminal UI.

Terminal Native

Built with Python and Textual. No web views or Electron overhead — keyboard shortcuts, slash commands, message history, and 500-message pagination.

PIN Lockout & Auto-Lock

Escalating lockouts after 5 (30s), 10 (5m), 20 (1h), and 50 (24h) failed attempts, plus configurable auto-lock idle timeouts and PIN changes without migration.

Audit Log

Security events are chained with HMAC-SHA256 inside the encrypted database so tampering or row deletion breaks chain verification.

Auto Discovery & Add by IP

UDP beacons on port 50505 advertise rotating code tags every 2 seconds, while Add by IP (I / /addip) pins addresses for routed overlays or non-broadcast subnets.

Safety Numbers & Blocking

Compare 60-digit safety numbers out-of-band, enforce verified-only mode, and block unwanted peers persistently across contact deletions.

Secure Deletion

SQLite runs in WAL mode with PRAGMA secure_delete=ON, row-bound AAD, and in-memory key clearing on lock, panic wipe, or shutdown.

Panic Password

Stored as v10: authenticated AES-256-GCM ciphertext under Argon2id. Entering it at unlock wipes the database and companion SQLite files and exits immediately.

Key Rotation

Generate fresh Ed25519 and X25519 keys on demand and broadcast a ROTATE frame signed with the old key. Undelivered rotations persist and can be retried.

Typing & Presence

Presence probes run every 3 seconds and typing indicators throttle to once per 1.5 seconds. Both are Ed25519-signed control frames rather than ratchet-encrypted payloads.

Outbox Retry

Timed-out messages queue in memory and retry every 10 seconds while a session is active, automatically dropping items for blocked or unverified contacts.

Reply & React

Use /reply <id> <text> and /react <id> <emoji> to sign message references directly inside the encrypted frame.

Search All

Press Ctrl+F to search decrypted messages across conversations (up to 50 results) or /find <text> within the active chat.

What LANMess is not: no file transfer, no images, no group chats, no native mobile app, no PIN recovery, no chat history export, no cross-VLAN UDP broadcast without a VPN/overlay or Add by IP, and no ratchet encryption on signed presence/typing frames.

Deep Dive FAQ

Technical details drawn directly from the LANMess source code.

1. App Setup & The Vault

What is the "Group Code" used for during setup?

The Group Code (12–256 characters) derives the shared network key via PBKDF2-HMAC-SHA256 with 600,000 iterations and salt lanmess-group-key-v1, which in turn derives the lookup key for discovery code tags and name hashes. Peers sharing the same group code can discover each other's rotating code tags.

What are the PIN strength requirements?

New and changed PINs must be 12–128 characters long, include lowercase, uppercase, a digit, and a symbol, contain at least 8 distinct characters, avoid four identical characters in a row, and avoid any substring pattern repeating three or more times.

What encryption is used for my local database?

Records in ~/.lanmess/lanmess.db are encrypted with AES-256-GCM under a random 32-byte master key, with AAD bound to record context (including contact ID and row ID for messages). The master key is wrapped in the vault table using Argon2id (time=3, memory=64 MiB, parallelism=4).

What happens if I fail my PIN multiple times?

Failed attempts are tracked persistently in SQLite: 5 failures trigger a 30s lockout, 10 trigger 5m, 20 trigger 1h, and 50 trigger 24h. Restarting the app does not reset the lockout timer.

What is the Panic Password and how does it work?

Set from the Menu, it is stored as v10: + Base64 of nonce || AES-256-GCM(Argon2id(pin, salt), 32-byte zero marker). Entering it at the unlock screen wipes the database, removes -wal, -shm, and -journal files, clears keys from memory, and exits.

2. Networking & Discovery

Can I use LANMess over a VPN like Tailscale, WireGuard, or ZeroTier?

Yes. LANMess uses UDP port 50505 for beacons and TCP ports 50510–50600 for peer frames. Over routed overlays where broadcast does not reach peers, use I or /addip with the peer's IP, TCP port, and 8-digit code.

What happens if my peer's IP address changes?

Unpinned contacts update their IP from live discovery beacons (2s interval, 15s TTL) or from the source IP of verified incoming frames. Contacts added via Add by IP are marked pinned=1 so their configured address is preserved.

How does the 8-digit "Add Code" work?

An 8-digit HMAC-SHA256 TOTP code rotates every 60 seconds from a 20-byte secret. Adding a peer sends a 32-byte challenge and HMAC proof over "REQ" + name + challenge using the code as key; the recipient checks both the current and previous 60-second window.

What ports do I need to allow in my firewall?

Allow UDP 50505 for discovery beacons and TCP 50510–50600 for peer connections (each instance binds one free TCP port in that range, or picks another automatically if busy on startup).

Does LANMess work across VLANs or subnets?

UDP broadcast on port 50505 stays within a broadcast domain unless routed or tunneled. Across subnets or VLANs, use Add by IP with a routable IP/port or connect through a VPN/overlay.

How do presence and typing indicators behave with respect to metadata?

Presence probes run every 3s (15s online window; 2 consecutive failures mark offline) and typing frames are throttled to once per 1.5s (3s display TTL). Both are signed with Ed25519 rather than wrapped in the message ratchet, so control-frame timing/metadata is visible to LAN observers.

How does the outbox retry queue work?

When a message times out (3s), it is queued in memory and retried every 10s while the session is established. Queued items for blocked or unverified contacts are dropped, and the in-memory queue clears on lock, stop, reset, or exit.

3. Cryptography & Security

What are "Safety Numbers"?

A 60-digit fingerprint derived by sorting both peers' Ed25519 public keys, hashing their concatenation with SHA-256, and formatting the first 60 decimal digits into 5-digit groups. Verify it out-of-band before trusting a contact on an untrusted network.

How does the hash ratchet provide forward secrecy?

Each step derives a per-message key via HMAC-SHA256 with label 0x02 and advances the chain key via HMAC-SHA256 with label 0x01, overwriting the prior chain state so past message keys are not re-derivable from a later state.

What does "Verified-only" mode enforce?

When enabled in the Menu, LANMess blocks starting chats, sending messages, and accepting incoming chat starts or messages unless the contact is marked verified.

What happens if signature or decryption verification fails on a message?

LANMess rejects the frame, logs SIG_FAILURE or DEC_FAILURE to the audit log, notifies you with an error, and leaves the ratchet state untouched without committing a message.

How does replay and gap protection work?

Incoming messages require a strictly increasing counter within a maximum gap of 1,000 steps, and control frames include a timestamp checked within a 60-second replay window.

How does key rotation work?

Key rotation generates new Ed25519 and X25519 keypairs, updates your encrypted identity, and sends a ROTATE frame signed with your previous Ed25519 key to non-blocked contacts. Undelivered rotations persist in pending_rotates until delivered or retried.

How does message padding work?

Plaintext is prefixed with a 4-byte big-endian byte length and padded with random bytes to a multiple of 256 bytes before AES-GCM encryption, hiding exact text lengths on the wire.

What rate limits protect against floods?

Add requests are rate-limited to one every 0.5s per peer IP and per sender name, and messages to one every 0.05s per peer IP, with each rate-limit table capped at 4,096 entries.

4. TUI Interface & Commands

What is the difference between "/clear" and "/clearall"?

/clear (or C) deletes only your local messages with the selected contact. /clearall sends a clear request to the peer and clears both sides once they accept (Y).

How do I reset all local data?

Press Ctrl+R or choose "Reset everything (Ctrl+R)" in the Menu. It drops and recreates database tables at schema version 10, runs VACUUM, clears in-memory keys, and returns to setup.

What do the contact badges and statuses mean?

Unread counts show as (n) up to (99+), * marks verified contacts, ● indicates an established online peer, and status tags include [active], [legacy], [waiting], [accept?], [chat req], [clear?], and [BLOCKED].

What is the maximum message length and frame limit?

Messages are capped at 8,192 characters, NUL bytes are rejected, and network frames are bounded to 64 KiB.

How do reply, reaction, deletion, and search commands work?

Use /reply <id> <text> and /react <id> <emoji> to reference message IDs, /del <id> or /del to delete local messages, /find <text> to filter the current chat, and Ctrl+F to search across all conversations.

5. Troubleshooting

Why does a message queue in the outbox or fail to deliver?

If sending times out (3s) or cannot reach the peer, LANMess marks the peer offline and queues the message in memory for retry every 10s while the session is active. Check that the peer is running, on a reachable IP/subnet, and not blocking TCP ports 50510–50600.

Why does a contact show as offline or "[legacy]"?

Peers go offline after two failed presence probes or 15s of silence, or if presence is toggled off. A [legacy] state indicates a previous chat record without an active in-memory session; when presence confirms the peer is back, LANMess can initiate a fresh X25519 handshake or you can press S.

How does blocking work when a peer is deleted or re-added?

Blocked peers are stored in a separate blocked table and persist even if you delete the contact. Manage them via /block, /unblock <name>, /blocked, or the Menu.

What does an audit chain failure indicate?

Each row in audit_log links to the previous row's HMAC using a key derived from the master key (starting from 64 zeros). If verify_audit_chain() fails, rows were modified, reordered, or removed outside the application.

What happens on session idle vs. app idle?

App-wide inactivity triggers auto-lock when past the configured timeout (default 15 minutes; configurable in the Menu). Per-chat inactivity warns after 30 minutes without closing the session; use /stop or T to end a chat.

6. Platform & Compatibility

Which CPUs are supported by the pre-built installers?

Pre-built installers target x86_64. On ARM64 / aarch64 hardware (Apple Silicon, Windows on ARM, Raspberry Pi / ARM Linux), install Python 3.9+ and run pip install lanmess or install from source.

What dependencies does LANMess require?

LANMess requires Python 3.9+, textual>=0.52.0, cryptography>=41.0.0, and argon2-cffi>=23.1.0 (with winotify on Windows).

Why might antivirus software flag the Windows installer?

PyInstaller-packaged executables occasionally trigger heuristic false positives. You can inspect the source on GitHub or install directly via pip install lanmess.

Is there a mobile app?

There is no standalone mobile app, though you can run the terminal UI on Android inside Termux via pip install lanmess (with termux-notification support).

7. General

Is LANMess free and open source?

Yes, LANMess is licensed under the MIT License with no accounts, subscriptions, or telemetry.

What happens if I forget my PIN?

There is no PIN recovery mechanism. Without the PIN to unwrap the master key via Argon2id, encrypted database records cannot be decrypted unless you restore a backup of ~/.lanmess or reset the database.

How do upgrades and backups work?

Installing a newer version preserves ~/.lanmess/lanmess.db and runs schema migrations automatically (current schema version is 10). Back up ~/.lanmess/lanmess.db along with active -wal and -shm files; reading a backup still requires your PIN.

Does LANMess access files outside ~/.lanmess or run background services?

No. LANMess stores its data under ~/.lanmess (directory mode 0700, database mode 0600) and runs only while the terminal app is open, without background daemons or telemetry endpoints.
