How everything works.

From installation to encrypted message delivery.

01

Vault Creation

Upon first launch, you set a strong PIN. LANMess generates a random 32-byte master key and encrypts it using Argon2id derived from your PIN.

02

Peer Discovery

The app broadcasts a UDP packet on port 50505. Other instances on the LAN hear this and cache your IP, port, and public keys automatically.

03

Secure Adding

To add a peer, you exchange an 8-digit TOTP code. This proves you share the same local network and are intentionally connecting to each other.

04

Encrypted Chat

A chat request triggers an X25519 ephemeral handshake. Once established, messages are encrypted with AES-GCM and signed with Ed25519.

Cryptographic
Architecture

LANMess does not rely on proprietary security through obscurity. It uses battle-tested, standard cryptographic primitives. Here is how a message is secured:

1

X25519 Handshake

An ephemeral key exchange creates a shared secret that is never sent over the network.

2

HKDF Derivation

The shared secret is expanded into independent send and receive hash chains using HKDF-SHA256.

3

AES-GCM & Hash Ratchet

Each message uses a fresh key from the ratchet, encrypts the padded payload with AES-GCM, and immediately advances the chain.

4

Ed25519 Signatures

Every control frame and message is signed with your long-term identity key to prevent tampering.

Deep Dive FAQ

Everything you need to know about LANMess. Mined directly from the source code.

1. App Setup & The Vault

What is the "Group Code" used for during setup?
The Group Code is used to derive the initial shared network key using PBKDF2-HMAC-SHA256 with 600,000 iterations. This ensures that only users who know the Group Code can generate the same discovery tags and securely format their packets. It acts as a shared secret for the local network group.

Why must my PIN be at least 12 characters long?
Your PIN unlocks the local vault (which contains your private keys). The config enforces PIN_MIN_LEN = 12 and requires at least 3 of: lowercase, uppercase, digit, symbol. A weak PIN makes the Argon2id encryption vulnerable to offline brute-forcing if your device is stolen.

What encryption is used for my local database?
Your SQLite database (~/.lanmess/lanmess.db) is fully encrypted. Every piece of data (identity, contacts, messages) is encrypted using AES-GCM. The master key for this data is wrapped using Argon2id (derived from your PIN) and stored in the vault table.

What happens if I fail my PIN multiple times?
LANMess implements escalating lockouts defined in PIN_LOCKOUT_STEPS:
- 5 failed attempts: 30-second lockout.
- 10 failed attempts: 5-minute lockout.
- 20 failed attempts: 1-hour lockout.
- 50 failed attempts: 24-hour lockout.
These are tracked in the database to prevent restarting the app to bypass them.

2. Networking & Discovery

Can I use LANMess over a VPN like Tailscale or ZeroTier?
Yes. LANMess operates on Layer 3 using UDP (port 50505) and TCP (ports 50510-50600). As long as your VPN creates a virtual LAN (Layer 2/3) where broadcast packets or direct IP routing can reach the peers, LANMess will function perfectly. You may need to use the "Add by IP" feature if UDP broadcast doesn't traverse the VPN.

What happens if my peer's IP address changes?
The UDP discovery mechanism automatically updates peer IP addresses every 2 seconds (DISCOVERY_INTERVAL). However, if you added the contact using "Add by IP", the contact is marked as pinned. Pinned contacts will not automatically update their IP. If the IP changes, you will have to re-add them manually.

How does the 8-digit "Add Code" work?
The 8-digit code is a TOTP (Time-Based One-Time Password) generated every 60 seconds (LOGIN_CODE_PERIOD = 60). When peer A wants to add peer B, A enters B's TOTP code. The code is verified using HMAC-SHA256 against the timestamp, proving that A and B share the same local network and that A knows B's current code. It prevents random scanning attacks.

What ports do I need to open in my firewall?
You need to allow:
- UDP 50505: For discovering peers (DISCOVERY_PORT).
- TCP 50510 - 50600: For sending and receiving actual messages (TCP_PORT_RANGE).
If you don't open these, peers will appear offline, or messages will fail to deliver.

3. Cryptography & Security

What exactly are "Safety Numbers"?
Safety numbers are a 60-digit fingerprint generated by hashing both your Ed25519 public key and your peer's Ed25519 public key. You must compare this number with your peer over a secure out-of-band channel (e.g., in person, or via a trusted phone call). If the numbers match, you are mathematically guaranteed that no Man-In-The-Middle (MITM) is intercepting your keys.

How does the "Forward Secrecy" hash ratchet work?
For every message sent or received, the symmetric encryption key is destroyed and replaced. The next key is generated by hashing the current key using HMAC-SHA256 (chain_advance). This means if an attacker steals your current key, they cannot decrypt any past messages, because the old keys were permanently deleted from memory.

What does "Verified-only" mode do?
When enabled in the Menu (m-vonl), LANMess will actively block any chat requests or messages from contacts that have not been explicitly marked as "verified" (where you've compared safety numbers). It is a strict zero-trust policy.

What happens if a message signature fails to verify?
If an incoming message fails Ed25519 signature verification, or if the AES-GCM decryption fails (indicating tampering), LANMess immediately blocks the contact. It assumes an active attack and shuts down communication with that peer to protect you. The event is logged in the Audit Log.

How does replay protection work?
Every message includes a sequential counter. If an attacker captures an old message and tries to send it again, LANMess checks the counter. If the counter is less than or equal to the last received counter, it rejects the message. There is also a 60-second time window check for control frames.

4. TUI Interface & Commands

What is the difference between "/clear" and "/clearall"?
/clear deletes the messages only on your local device. The peer still has their copy.
/clearall sends a CLEAR_REQUEST to the peer. If the peer accepts, both sides wipe the conversation from their local databases. It requires a mutual agreement to prevent data loss.

How do I completely reset LANMess?
You can press Ctrl+R or open the Menu and select "Reset everything". This drops all tables (identity, contacts, messages, vault), performs a database VACUUM, and zeroes out the cryptographic keys in memory. It is irreversible.

What do the contact statuses mean?
Based on the exact source code in tui.py:

- [active]: The X25519 handshake is complete, the ratchet is set (session_established=1), and you can send messages.
- [waiting]: pending == 1. You sent an add contact request to them, and you are waiting for them to accept.
- [accept?]: pending == 2. They sent you an add contact request, and you need to press 'Y' to accept.
- [chat req]: incoming_request == 1. They want to start a chat with you.
- [legacy]: chat_started is true, but session_established is false. The chat started, but the secure session dropped (e.g., app crashed or network loss). Press 'S' to restart the handshake.

What is the maximum message length I can send?
The maximum message length is 8,192 characters (MAX_MESSAGE_LEN = 8192). If you try to send a longer message, LANMess will prevent it to avoid overwhelming the frame size limit.

How do I accept a chat request or clear request?
When you have a pending request (chat or clear), a yellow indicator appears next to the contact. Press Y to Accept or X to Reject. You can also do this via the Menu.

5. Troubleshooting

Why does it say "Message not delivered: no response"?
This means the peer's TCP server is unreachable or blocked. Potential causes:
- They closed the app.
- Their firewall is blocking TCP ports 50510-50600.
- They are on a different subnet/VLAN.
- You are no longer on the same LAN.

Why is my peer showing as offline?
LANMess uses a presence system that pings every 3 seconds (PRESENCE_INTERVAL). If no response is received within 15 seconds (ONLINE_WINDOW), the peer is marked offline. Check if UDP port 50505 is open, or if they paused their presence in the menu.

Why did I get blocked by a contact?
If the app detects a signature failure, decryption failure, or severe replay attempt from your IP, it automatically blocks you and prevents further communication. This only happens if the cryptographic integrity of the session is compromised.

What does the "Audit Log" warning mean?
The app maintains an HMAC-chained audit log. If someone tries to manually delete or modify database rows, the chain breaks. A warning means your database has been tampered with outside of the app.
